Setup

Term connects to a computer you own, where your agents run. This guide sets up that computer and adds it to Term. It takes about 15 minutes. Each step says what to do if it fails; the troubleshooting table at the end lists the messages Term shows.

The examples call the computer studio. Use your own computer's name.

1 A computer that stays on

Use a Mac or a Linux computer that stays on and awake while you are away. Your agents run there; Term only shows them.

  • Mac: in System Settings › Energy (or Battery › Options on a laptop), turn on Prevent automatic sleeping when the display is off. A laptop must stay plugged in.
  • Linux: turn off automatic suspend in your desktop's power settings.

If it fails: a computer that sleeps drops every connection. If Term stops reaching it after a while, check its sleep settings first.

2 Reach it from your phone

Term connects over SSH. First turn on the computer's SSH server. On a Mac: System Settings › General › Sharing › Remote Login, on. On Linux:

# Ubuntu or Debian
sudo apt install openssh-server

# Fedora
sudo dnf install openssh-server
sudo systemctl enable --now sshd

Then pick how your phone reaches the computer.

From anywhere: Tailscale (recommended)

  1. Install Tailscale on the computer and sign in.
  2. Install Tailscale on your iPhone from the App Store, sign in with the same account, and turn it on.
  3. In the Tailscale app, find your computer. Its address is its name (for example studio, through Tailscale's MagicDNS) or a number starting with 100.. Either works in Term.

At home only: the same Wi-Fi

If the phone and the computer share a network, use the computer's local address:

  • Mac: System Settings › Wi-Fi › Details next to your network, or run ipconfig getifaddr en0.
  • Linux: run hostname -I and use the first address.

This stops working when you leave home. Tailscale keeps working everywhere.

You also need your user name on the computer. Run whoami to see it.

If it fails: check that Tailscale is on in the iPhone's Tailscale app, and that the computer shows as connected there. If the name doesn't work, use the 100. address.

3 Install mosh and tmux

mosh keeps your session alive when the phone changes networks or iOS suspends Term. tmux keeps your sessions running on the computer and lets Term list them. tmux is optional but recommended. On a Mac, install Homebrew first if you don't have it.

# Mac
brew install mosh tmux

# Ubuntu or Debian
sudo apt install mosh tmux

# Fedora
sudo dnf install mosh tmux

Check the version with mosh-server --version. Term needs mosh 1.4.

mosh uses UDP ports 60000 to 61000. If the computer runs a firewall, allow them. On a Mac with the firewall on: System Settings › Network › Firewall › Options, add mosh-server and allow incoming connections. On Linux:

# ufw
sudo ufw allow 60000:61000/udp

# firewalld
sudo firewall-cmd --permanent --add-port=60000-61000/udp
sudo firewall-cmd --reload

If it fails: if your system only offers a mosh older than 1.4, or UDP stays blocked, set the host's Transport to SSH in step 5. Everything works over SSH except surviving network changes and iOS suspends.

4 Run the host kit

The host kit, term-host, checks the computer and installs what lets Term show your agents' status. Install it with:

HOST_KIT_INSTALL_COMMAND

Then run:

term-host check

It checks that the SSH server answers, that mosh-server and tmux are installed and which versions, whether Tailscale is installed and signed in, and which agents (Claude Code, Codex, omp) it finds. For anything missing, it prints the command that installs it.

When the check passes, run:

term-host install

This sets up agent status for the agents it found (see step 6). It adds to your existing agent settings without overwriting them and keeps a backup. term-host uninstall removes exactly what it added.

If it fails: run each install command term-host check prints, then run the check again. If it still fails, send its output to support.

5 Add the computer in Term

Open Term's Settings: tap the terminal with three fingers (or double-tap ⌘ on the key bar above the keyboard) and choose Settings.

Add the host

Go to Settings › Hosts, tap +, and fill in:

  • Alias: a short name you'll type, like studio.
  • HostName: the address from step 2.
  • Port: leave empty for 22.
  • User: your user name from whoami.
  • Key: leave as it is.
  • Password: your computer password, for the first connection only.
  • Transport: Mosh (or SSH, see step 3).
  • Command: tmux new -A -s main, so every connection opens the same tmux session.

Tap Save. In Term's terminal, type mosh studio (or ssh studio). The first time, Term saves the computer's identity and shows Pinned studio's host key SHA256:….

Switch to a key

A key is safer than a password and lets you turn password login off later. The private key never leaves the iPhone's Keychain.

  1. Go to Settings › Keys, tap +, then Generate Ed25519 Key, then Generate. (Import Private Key takes a key you already have.)
  2. Open the new key and tap Copy under its public key.
  3. In the session you just opened, run these lines, pasting the public key between the quotes: 
    mkdir -p ~/.ssh
echo 'PUBLIC KEY' >> ~/.ssh/authorized_keys
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
    Or tap Share on the key to send it to the computer and run the lines there.
  4. Open the host in Settings › Hosts, clear the Password field and tap Save.
  5. Connect again. It connects with the key alone.

Once a key exists, Term signs in with it and no longer tries the password; with more than one key, pick one in the host's Key field. Once connected, the tmux tab in the menu lists every tmux session on the computer.

If it fails: find the red message in the terminal in the troubleshooting table. The most common is authentication failed: the User is wrong, or the key line didn't reach ~/.ssh/authorized_keys.

6 See your agents

Run your agents inside tmux on the computer. Term's tmux tab then shows, under each session's name, what its agent is doing, and the answer or question when it finishes, fails or asks you something. The tab's icon counts the sessions waiting on you. A long press shows the whole answer.

Claude Code and Codex

term-host install (step 4) adds hooks to Claude Code and Codex that report their state to Term. Start a new agent session afterwards.

omp

term-host install also installs Term's omp extension. To install it by hand from a copy of the source, run in its folder:

ln -s "$PWD/integrations/omp/term-agent.ts" ~/.omp/agent/extensions/term-agent.ts

New omp sessions load it. Also set omp to repaint only the screen when the phone's keyboard rises or the phone rotates:

omp config set tui.resizeScrollback preserve

If it fails: make sure the agent runs inside tmux (outside tmux nothing is reported) and that you started it after installing. For omp without the extension, Term still shows working, asks you or idle from omp's terminal title.

7 Screen: see your Mac

The Screen tab streams your Mac's displays to the phone and lets you drive them. It needs a small Mac app, Term Screen Host, which streams through your existing SSH connection and opens nothing new on the network.

  1. Download Term Screen Host from SCREEN_HOST_DOWNLOAD_URL, open it and install it.
  2. In System Settings › Privacy & Security, allow Term Screen Host under Screen & System Audio Recording and under Accessibility.
  3. So the clipboard can follow you: allow Term Screen Host's first paste on the Mac, and on the iPhone set Settings › Apps › Term › Paste from Other Apps to Allow.
  4. To use a locked Mac: turn on System Settings › General › Sharing › Screen Sharing. Term asks once for the Mac account's password and keeps it in the iPhone's Keychain, behind Face ID.
  5. In Term, open the menu, choose Screen, and pick your Mac.

If it fails: Install Term Screen Host on studio means the Mac app is not running: open it, or install it again. Term Screen Host needs access on studio or Allow Term Screen Host in Screen & System Audio Recording and Accessibility means one of the permissions above is still missing. Can't reach studio is a connection problem; see the table below.

8 Troubleshooting

Connection errors show in red in the terminal; a silent mosh session shows a bar at the top. Find the message below.

Term showsWhat to do
host key changed: expected ssh-ed25519 AAAA…, server presented ssh-ed25519 AAAA… The computer at that address has a different identity than the first time. This is expected after reinstalling its system or if the address now points to another computer. If you know why, open the host in Settings › Hosts, tap Forget Host Key, and connect again. If you don't, stop and check the address.
authentication failed The computer refused the sign-in (other SSH apps say Permission denied (publickey)). When Term has a key it signs in with the key, not the password. Check that User matches whoami on the computer, that your public key is one line in ~/.ssh/authorized_keys, and run chmod 700 ~/.ssh; chmod 600 ~/.ssh/authorized_keys.
no key or password for this host Make a key in Settings › Keys, or enter a password on the host.
mosh-server not found on the host (tried mosh-server, /opt/homebrew/bin/mosh-server, /usr/local/bin/mosh-server) Install mosh (step 3). If it is installed somewhere else, run which mosh-server on the computer and put that path in the host's Mosh › Server field.
No contact for 8 s or Reconnecting… at the top, over and over, right after connecting with mosh SSH worked but mosh's UDP traffic is blocked. Allow UDP ports 60000 to 61000 in the computer's firewall (step 3), or set the host's Transport to SSH. If it appears later in a session, the network dropped: Term reconnects by itself, or tap Reconnect.
cannot connect to studio:22: Connection refused The computer is reachable but its SSH server is off. Turn on Remote Login on a Mac, or start the SSH server on Linux (step 2).
cannot connect to studio:22: timed out or handshake timed out The phone can't reach the computer. Check that Tailscale is on in the iPhone's Tailscale app, that the computer is awake and online, and that the address is right. On the same Wi-Fi, check the phone isn't on cellular.
cannot resolve studio The name is unknown to the phone: Tailscale is off on the iPhone, or MagicDNS is off in Tailscale. Turn Tailscale on, or use the computer's 100. address.
Can't reach studio or Install Term Screen Host on studio in Screen See step 7. Check that a terminal connects to the same host first.
